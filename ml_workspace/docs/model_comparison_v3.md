# Classifier comparison on splits_v3

## Decision

Use **TF-IDF + logistic regression** as the provisional backend model. It leads all saved targets,
has work-type micro-F1 0.9785 versus 0.8473 (embeddings) and 0.6456 (CatBoost), has the best measured
multi-label subset F1, loads locally on CPU, and requires no external download. This is not evidence
of superior real-world accuracy: every test target was generated by `weak_rules_v3`.

## Compatibility audit

All artifacts record format 2, `taxonomy_v2`, identical target class lists/configuration, Python
3.13.16, NumPy 2.1.3, pandas 2.2.3, scikit-learn 1.6.1, and joblib 1.6.0. Their identical set of
49,218 supervised fit IDs (SHA-256 `fe05c7...0227`) is wholly contained in the current training
partition. Test supports and excluded-invalid counts also match. The dataset manifest records
`dataset_v3`, `weak_rules_v3`, master SHA-256 `11555a...3e83`, and split-manifest SHA-256
`24dbe5...0640`. Artifacts do not embed these hashes, so the fingerprint association is strongly
supported but not cryptographically self-contained.

## Multi-label behavior

Exactly nine eligible test rows have at least two true work types. Saved subset micro-F1 is .7742
for TF-IDF, .5143 for embeddings, and 0 for CatBoost. Recomputed TF-IDF results are 2/9 exact,
seven underpredictions, zero overpredictions, and 14 multi-label predictions across all 10,168
eligible rows. CatBoost is 0/9 exact, underpredicts all nine, and predicts 16 multi-label rows
elsewhere. Embeddings prediction arrays were not saved and its runtime could not be installed on
this ARM environment, so its exact-match, under/over, and total multiple-prediction counts are
unavailable. Missed TF-IDF secondary labels include `floor_covering_install` for a floor screed,
`wall_putty` for acrylic primer, `wall_painting` for putty/primer products, and `wallpapering` for
wallpaper primer. No semantically implausible combination occurred among the nine TF-IDF rows;
the dataset is too small to generalize that observation.

## Deployment measurements and selection limits

Under Python 3.13.11/scikit-learn 1.6.1 on the same CPU, TF-IDF cold load was .197 s, mean single
inference 3.78 ms, mean 12-item batch 4.11 ms, and peak process RSS about 250 MiB. Direct scoring of
10,168 prepared test rows took .083 s. CatBoost cold load was .041 s and direct scoring took .026 s;
its structured fields are available but too weak for central work-type assignment. Embedding saved
feature preparation took 307 s and evaluation 1.00 s, but these are not comparable online latency
benchmarks. It also adds a 489 MB artifact and torch/sentence-transformers runtime.

TF-IDF is selected without an arbitrary composite score: it materially leads work-type quality,
multi-label subset F1, every overall target, and remains operationally simpler than embeddings.
The adapter's real catalog fields match its inference schema; missing optional fields are accepted.

Next validation should human-label a stratified sample, oversample rare and genuine multi-label
products, review empty-work predictions, and report uncertainty intervals. Do not tune thresholds
on the smoke examples or claim real-world accuracy from these weak-label metrics.
