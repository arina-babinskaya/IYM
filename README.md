# RepairCalc

Калькулятор ремонта для каталога Максидома. Задаёшь комнату (размеры, тип, вид ремонта),
сервис выбирает нужные работы и подбирает под каждую товары из каталога. Потом считает,
сколько упаковок купить и сколько это стоит. Товары можно поменять вручную, а в карточке
товара можно отдельно посчитать, сколько его нужно на заданную площадь.

Сервис работает отдельно от сайта и отвечает по REST/JSON. Внутри FastAPI, база PostgreSQL
(в Docker) или SQLite (локально), а привязку товаров к видам работ делает TF-IDF-классификатор.

## Как запустить

### Через Docker

Это основной способ.
Нужен Docker Desktop. Каталог организаторов положите в `data/catalog.json`.

```
docker compose up -d --build          # API на http://localhost:8000, PostgreSQL на порту 5433
docker compose run --rm ingest        # один раз: загрузить каталог и привязать товары
```

Загрузка с привязкой всего каталога идёт несколько минут. Когда она закончится, откройте
http://localhost:8000.

Ещё пригодится:

```
docker compose logs -f api            # логи
docker compose down                   # остановить; база останется в томе pgdata
docker compose down -v                # остановить и удалить базу
```

### Без Docker

На Windows хватит запустить `start.bat`. Он сам создаст виртуальное окружение, поставит
зависимости и откроет браузер. На других системах:

```
pip install -r requirements.txt
python run_local.py                   # http://localhost:8000
python run_local.py --reload-data     # пересоздать базу и загрузить каталог заново
```

При первом запуске каталог берётся из `data/catalog.json` (или `data/catalog.xml`). Если их нет,
грузится маленький пример из `mock_catalog/` на 27 товаров. Его же используют тесты.
Если нужно быстро проверить на части каталога, перед запуском задайте `RC_LOCAL_LIMIT=5000`.

### Загрузка каталога вручную

```
python -m scripts.ingest --file data/catalog.json         # JSON организаторов или YML, формат определяется сам
python -m scripts.ingest --file data/catalog.json --limit 2000
python -m scripts.ingest --download                       # скачать YML по ссылке и загрузить
```

Товары, которых нет в новом файле, становятся неактивными. Добавленные вручную через админку
при перезагрузке не удаляются.

### Подключение API и настройка 


1. В корне проекта нужно создать папку data/catalog.json , где catalog.json - это исходный датасет, предоставленный максидомом
2. В корне проекта нужно сделать `cp .env.example .env` . В файле .env расскоментировать помеченные строки и вставить API GigaChat

## Как считается смета

1. **Работы.** Для каждой комнаты и вида ремонта (косметический или капитальный) есть набор работ по этапам:
   демонтаж, черновые, чистовые, электрика и так далее. Часть отмечена по умолчанию, остальные можно добавить.
2. **Кандидаты.** Под каждую работу и материал берутся товары, которые классификатор к ним привязал:
   только активные, в наличии и с ценой. Если точной привязки нет, берутся товары, совместимые по виду работ,
   а потом товары того же материала без указанного вида работ. Такие товары идут в конец списка.
3. **Выбор товара.** Ранжировщик (`app/ml/ranker.py`) ставит каждому кандидату баллы. Учитывается, что товар
   типичный для этой работы, у него есть фасовка (есть чем считать количество), он подходит этой комнате,
   его разумная цена за единицу, а также рейтинг и наличие. Штрафы получают декоративные товары в обычной
   отделке, уличные товары в квартире и явно невлагостойкие во влажных комнатах. Каждый балл попадает
   в пояснение «почему выбран» на странице.
4. **Количество.** Формулы расхода по нормам лежат в `app/engine/baseline.py`. Площадь стен считается
   за вычетом окон и дверей, к расходу добавляется запас, результат округляется до целых упаковок.

## API

Полная документация с примерами: http://localhost:8000/docs

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/v1/estimate` | Смета по комнатам: позиции по этапам, количество, цена, пояснение `why` |
| GET | `/api/v1/works?room_type=&renovation_type=` | Какие работы доступны для комнаты и какие выбраны по умолчанию |
| POST | `/api/v1/estimate/options` | Варианты замены товара в строке сметы, с фильтрами и сортировкой |
| GET | `/api/v1/taxonomy` | Справочник этапов, видов ремонта, работ и материалов |
| POST | `/api/v1/product/{id}/calc` | Расчёт в карточке товара: размеры → упаковки и цена |
| GET | `/api/v1/products?q=`, `/api/v1/products/{id}` | Поиск и карточка товара |
| GET/POST/DELETE | `/api/v1/admin/products…` | Админка: товары, ручное добавление, подтверждение привязки |
| POST | `/api/v1/admin/autobind` | Автопривязка непривязанных товаров |
| GET | `/api/v1/admin/stats` | Сколько товаров привязано |
| … | `/api/v1/admin/catalog/…` | Классификация товаров по категориям каталога (модель участника 3) |
| GET | `/health` | Работают ли база и подключение к нейросети |

Пример запроса сметы:

```json
POST /api/v1/estimate
{
  "renovation_type": "cosmetic",
  "rooms": [{"room_type": "bathroom", "length_m": 2, "width_m": 2.5, "windows": 0, "doors": 1}]
}
```

## Структура

| Путь | Что там | Кто отвечает |
|---|---|---|
| `app/api/` | адреса API | 1 |
| `app/catalog/` | загрузка каталога (JSON, YML), разбор характеристик в числа, запросы к базе | 1 |
| `app/models.py`, `app/db.py`, `app/schemas.py` | таблицы и формат запросов и ответов | 1 |
| `app/ml/ranker.py` | ранжировщик товаров | 1 |
| `app/plans.py`, `app/taxonomy.py` | какие работы бывают и какие материалы им нужны | 1, 2, 3 |
| `app/engine/baseline.py` | формулы расхода материалов | 2 |
| `app/ml/tfidf.py`, `ml_workspace/` | классификаторы и их обучение | 3 |
| `app/llm/` | GigaChat: запасная привязка и пояснения (по умолчанию выключены) | 3 |
| `app/static/index.html` | страница калькулятора и админки | 4 |
| `scripts/` | загрузка каталога, допривязка, оценка качества | 1, 3 |
| `mock_catalog/` | маленький каталог для тестов и демо без данных | все |
| `tests/` | автотесты | все |

## Настройки

Всё задаётся переменными окружения с префиксом `RC_`, пример в `.env.example`. Главные:

- `RC_DATABASE_URL` — база. По умолчанию SQLite, в Docker PostgreSQL.
- `RC_CATALOG_PATH` — откуда грузить каталог.
- `RC_AUTOBIND_MIN_CONFIDENCE` — порог уверенности классификатора для автопривязки, по умолчанию 0.7.
- `RC_GIGACHAT_ENABLED`, `RC_GIGACHAT_CREDENTIALS` — включить GigaChat. Ключ хранится только в `.env`,
  в репозиторий его не коммитим.

## Тесты

```
pytest
```

Тесты используют `mock_catalog` и временную SQLite, ни реальный каталог, ни интернет им не нужны.
